## 5. 사고 기록 — 내가 결과물을 한 번 날렸다

밤샘 2차에서 Codex 가 사례 17개를 다 써 놨는데, **커밋하지 않은 채 브랜치를 옮기고 `git checkout <브랜치> -- <파일>` 로 같은 파일을 덮어썼다.** stash·사본·git 오브젝트 어디에도 없어 복구 불가였다.

- 손실이 작았던 이유 = Codex 가 «어느 문항에 어떤 사건을 붙였는지» **매니페스트**를 남겨서, 재작업이 창작이 아니라 복원이었다.
- 🔑 **규칙: Codex 산출물은 검증보다 커밋이 먼저다.** 1차에서는 지켰고 2차에서 어겼다.
- 재작업하면서 지난번 내 브리프가 막아 뒀던 `vibe-chNN.ts` 범위를 풀어 12개를 더 채웠다(17 → 29).

## 7. Codex 운용 — 이번에 굳은 것

| 대상 | 가능? |
|---|---|
| workspaceRoot 안 **일반 파일** 쓰기 | ✅ |
| workspaceRoot **밖** 쓰기 | ❌ `Read-only file system` |
| **git 메타데이터**(브랜치·커밋) | ❌ `index.lock: Read-only` |
| 외부 망(`push`·`gh`·검색) | ❌ |

**되는 방식** = Codex 는 파일만, git 은 사람이. 산출물은 **받는 즉시 커밋**(§5). 여러 PR 로 쪼갤 거면 «어느 파일이 어느 PR 소속인지» 매니페스트를 남기게 할 것.

🔑 **이번 밤샘에서 Codex 가 가장 값졌던 지점은 «안 한 것»이다** — 사례 26개를 비운 판단, 그리고 감사에서 내 PR 의 과장된 «0건» 주장을 잡아낸 것. 완료 보고는 디스크에서 확인하되, **비관적인 보고는 대체로 옳았다.**
