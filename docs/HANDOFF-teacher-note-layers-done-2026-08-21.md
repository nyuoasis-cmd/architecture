## 3. 실제로 만든 것

### 3.1 스키마 (`server/src/data/teacher-explain/types.ts` · client 짝은 `teacher-explain-fetch.ts`)

- `layer1` = `opening` · `steps[2~4]{act, say}` · `closing`
- `layer2` = `why[1~3]{heading, body(≤1200)}` · `stopHere(≤800)`
- `layer3` = `incidentLink(≤800)`
- 🚨 **전부 optional.** 그리고 **기존 필드의 길이 상한은 안 올렸다** — 층이 새 필드를 갖게 돼서
  늘릴 이유가 없어졌다. 앞 핸드오프 §4.2 의 「상한 몇 개만 올리면 된다」는 «기존 필드를 늘려 쓴다»
  전제였고, 층별 새 필드로 가면서 그 전제가 바뀌었다. 필드 의미를 안 바꾸는 쪽이 정직하다.

### 3.2 화면 (`client/src/components/learn/TeacherExplainPanel.tsx`)

- 층이 하나라도 있으면 **층 탭 3개**, 없으면 **지금까지의 카드 배치 그대로**(폴백).
- 층 2 의 기존 칸들(개념·작동 방식·오개념·메모)은 버리지 않고 **«배경» 서랍**으로 접어 둔다.
- 🚨 **비활성 층도 DOM 에 둔다**(`is-hidden` + CSS). 안 그러면 🖨️ 인쇄가 «지금 열어 둔 층» 하나만
  찍는다 — 교사가 종이로 들고 가는 것은 수업 전에 읽을 층 2 인데 그게 빠진다.
  이건 처음 만들 때 실제로 그렇게 만들었다가 완료 조건을 미리 적어 둔 덕에 잡았다.
- 층이 있으면 「1분 훑기 / 3분 정독」 토글을 감춘다 — 층 자체가 «언제 읽는가»를 이미 갈랐다.

### 3.3 계약 (`server/src/lib/teacherExplainContract.test.ts` ⑦~⑩) · 전체 270개 초록

- ⑦ 층 1 이 있으면 층 2 도 있다 (대본만 있고 «왜»가 없는 노트 금지)
- ⑧ 층 2 의 첫 문장에 「프로그램·서버·개발자·시스템·소프트웨어·알고리즘」 금지 (§7 검사 1의 기계판)
- ⑨ 화면이 세 층을 전부 그린다 (데이터만 늘고 교사가 보는 건 그대로인 상태 금지)
- ⑩ 층을 가진 노트 수를 찍는다 (0개에 초록인 계측 금지)
- 변이 3건으로 이빨 확인. **⑧ 은 작업 중 실제로 한 번 물었다**(`ch08_q03`) — 고쳤다.

🚨 **«모든 노트에 층이 있다»는 계약을 두지 않았다.** 지금 131/131 이지만, 걸면 새 문항마다
CI 가 없는 글을 요구한다(교안 계약 ⑯ 의 실패). ⑦~⑨ 는 전부 «있으면 이래야 한다» 꼴이고,
