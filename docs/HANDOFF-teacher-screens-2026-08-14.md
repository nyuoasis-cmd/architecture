## 2. 되돌리지 말 것

- 🚨 **화면 문구의 「세션」** — 교사도 학생도 그 말을 쓰지 않는다. 하는 것은 **수업**이다.
- 🚨 **확인 없는 종료·삭제** — 상세의 종료는 `confirm()` 도 없이 즉시 실행됐다. 학생은 그 순간부터 못 들어온다.
- 🚨 **진행 중 카드의 삭제 버튼** — 종료 옆 한 칸 차이로 반 전체 기록이 사라진다.
- 🚨 **「읽은 문항」** — 진도 행은 문항 화면을 **여는 순간** 생긴다. 「읽은」은 앱이 모르는 것을 안다고 말하는 문구다.
- 🚨 **시연작 입구를 밖에 다시 만드는 것** — 지금 있는 것이 시연작이다(수업 현황 상세의 「👀 학생 화면 미리 보기」).

| # | 결정 | 왜 | 되돌리려면 |
|---|---|---|---|
| 1 | 통계 3셀 = 참여 학생 / **열어 본 문항** / 진행 중 | 이 앱엔 「만든 앱」에 해당하는 산출물이 없다. 「읽은」이 아닌 이유는 §2 | 라벨 문자열 3곳 + 계약 두 줄 |
| 2 | 활동 문구 = `{이름}님이 「{문항}」 퀴즈 완료 / 읽음` | 퀴즈 점수가 있으면 「퀴즈 완료」, 아니면 「읽음」. 제목을 못 찾으면 qa_id 라도 내보낸다(빈 따옴표 방지) | `session-activity.ts` 한 곳 |
| 3 | 삭제 버튼 = **종료된 수업에만** | 진행 중 카드에서 종료 옆 한 칸 차이 = 반 기록 영구 삭제 | `SessionCard` 의 `isActive` 갈래 |
| 4 | 「👀 학생 화면 미리 보기」 **문구 유지** | 2026-08-11 prod QA(신입샘 t2)에서 「시연」이 교사에게 두 가지로 읽혀 일부러 바꾼 문구다. **실사용 관찰이 용어 규칙보다 무겁다** | 문구 1곳(+ `ui-glossary §H` 와의 불일치는 그대로 남는다) |
| 5 | C-10 「이 학생 이어주기」 = **구현하지 않음** | 학생 신원이 참여 토큰 쿠키 하나이고 진도가 거기 매달려 있다. 두 기록을 잇는 화면을 만들려면 **학생 식별 모델부터** 바꿔야 한다 — 지금 필요하다는 관찰이 없다 | 새 에픽 |

정책 문서(`shared/BUILDER-UX-POLICY.md §11`)에 architecture 절을 신설하고 4·5의 근거도 함께 적었다.


**새 필드 실측**(같은 로컬 서버 + 공유 prod DB, QA 마커 세션):

```

```

**브라우저 확인**(DEV 로그인 → 두 화면):

- `/teacher` — `max-w-4xl` · 「내 수업」 + 「19개 수업 · 진행 중 19개」 · 카드 radius 12px/padding 20px ·
  통계 3셀 · 아바타 4 + `+3` · 「한지호님이 「…」 퀴즈 완료 · 방금」
- `/teacher/session/:id` — `max-w-[900px]` · 「← 내 수업」 · 22px 제목 + 진행 중 뱃지 · 코드 뱃지 · 👤 7명 · 📄 22개 문항 ·
  통계 3열 · 학생 현황 행(이름 · 상태 뱃지 · N/22 문항)
- 종료 확인 모달 — 제목·설명 정확, **포커스가 「취소」에 있고**, 본문 스크롤 잠김(`overflow:hidden`),
  ESC 로 닫히며 **수업은 진행 중 그대로**
- 종료된 카드 — opacity `0.55` · QR·종료 버튼 없음 · 「삭제」만 · 「종료된 수업이에요」 · 위에 「종료됨」 라벨
- 삭제 — 카드 안 「삭제」를 눌러도 **상세로 튀지 않고**(stopPropagation) 모달이 뜨고,
  확인하면 카드가 사라진다. DB 잔존 0 확인

🚨 **스크린샷은 못 찍었다** — Chrome 확장의 스크린샷 주입이 5초 타임아웃으로 계속 실패했다(같은 탭에서 JS 실행·DOM 읽기는 정상).
그래서 위 확인은 **DOM 텍스트와 계산된 스타일**로 했다. 픽셀 눈검사(QA-POLICY 6번 칸 「사람눈」)는 아직 안 한 것으로 세어야 한다.

심어 둔 QA 데이터(수업 2건 + 참여자 7명 + 진도 22행)는 **전부 삭제 확인**(204 · 마커 잔존 0).
