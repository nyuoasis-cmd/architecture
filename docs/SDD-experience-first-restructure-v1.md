# SDD — 체험 중심 재구조화 v1 (experience-first restructure)

2026-08-17 grill-me 인터뷰(jery × Claude)로 확정. 질문 13개 전부 사용자 확정.

## 0. 한 줄 방향

앱의 본체를 «읽는 화면»에서 «체험하는 화면»으로 옮긴다.
학생(미성년)은 실계정·실서비스 대신 **실제와 근접하게 작동하는 유사 UI**로 체험하고,
교사(비전공)는 **설명 노트 하나**로 공부하며, AI 보조는 **체험 안**에 산다.

## 1. 확정 결정 (13건)

### 범위·지도

1) **전 강 일괄 설계, 구현은 실습강부터** — 23강 전체의 체험 형태를 지도(배정표)로 먼저 확정한다. 강마다 체험을 재발명하지 않기 위함.
2) **체험 부품은 3종으로 고정**:
   - **터미널형** — 치는 체험 (현 12강 실습실 계열)
   - **유사 페이지형** — 누르는 체험 (가짜 GitHub·가짜 배포 화면 등)
   - **견학형** — 진짜 외부 링크, 보기만. **로그인·입력이 전혀 없는 공개 페이지만.**
3) **유사 페이지형은 견학 링크와 반드시 짝** — 순서는 «진짜 페이지를 먼저 보고 → 유사 페이지에서 진행». 몰입의 핵심 장치. 지도에서 유사 페이지형 강은 짝 링크 칸이 필수.
4) **모든 강에 체험 탭이 있다** — 터미널·유사 페이지가 없는 이론강은 견학형(기존 견학 데이터)이 곧 그 강의 체험. 전 강이 같은 화면: «읽기 → 체험 → 퀴즈». 강마다 탭이 출렁이지 않는다.

### 화면 구조 (철거 4 + 유지 3)

5) **탭 재편 확정**:

| 지금 | 재설계 후 |
|---|---|
| 읽기 | 유지 |
| 견학 | **체험 탭 앞부분으로 흡수** |
| 실습 | **체험 탭 본체** |
| 내 차례 | **철거** — 역할(짧게 써서 AI 피드백)은 체험 안 미션으로 흡수 |
| 퀴즈 | 유지 |
| AI 챗봇 (좌측 패널) | **완전 철거** — AI 보조는 체험 안으로 |
| 설명 노트 (교사) | 유지 — 이번 방향의 축 |
| 실습 현황 (교사) | **철거** — 필요분만 «수업 현황» 대시보드로 이관 |

학생이 보는 것 = **읽기 → 체험 → 퀴즈** 세 걸음 + 교사 전용 노트 탭 하나.

### 터미널형 상세

6) **AI 교정 = 2단 판정 + 다시 치게 하기**:
   - 1단: 뻔한 오타(`sl`→`ls`)는 **로컬**이 즉시 잡는다 — 호출 0, 지연 0, 교실 30명이 쳐도 수업이 안 끊긴다.
   - 2단: 로컬이 못 알아듣는 입력(자유 문장 포함)만 **Haiku**가 «무엇을 하려던 건지» 해석.
   - 고침 형태: **자동 실행하지 않는다.** 「혹시 `ls` 를 치려던 건가요?」라고 알려주고 **손은 학생이** 다시 친다. 수업 목표가 «직접 쳐 본다»이므로.
7) **터미널 UI = 한 터미널, 두 목소리** — 화면은 셸 하나. AI가 말하는 줄은 전용 프리픽스+색(예: `ai▸`)으로 셸 출력과 확실히 구분. 근거:
   - 진실성 — 「cat 출력은 진짜 파일, AI 호출은 진짜 호출」 원칙이 화면에서 유지되려면 사실(명령 출력)과 AI의 말이 눈으로 갈라져야 한다.
   - 교재성 — 실습강이 가르치는 것이 «AI에게 시키는 방식»이라, 내 명령 vs AI 응답의 구분 자체가 교육 내용.
   - 에이전트 CLI «모양»(들여쓴 실행 블록 등)은 주제가 그것인 강에서만 요소를 빌린다. 풀 모사는 하지 않는다.

### 유사 페이지형 상세

8) **작동 깊이 = 대본형 + 산출물 슬롯, 실제 UX를 최대한 충실히 재현**:
   - 기본은 대본형 — 정해진 흐름의 버튼·입력만 작동, 공용 렌더러 + 대본 데이터 한 벌로 강마다 찍어낸다.
   - 유사 페이지 정의에 **«학생 산출물 슬롯»을 표준으로** 둔다 — 학생이 터미널에서 만든 것(규칙 파일 등)이 유사 페이지에 반영(«내가 쓴 게 저기 올라갔다»). 반영은 전부 그 학생 브라우저 안에서만.
   - 실제와 똑같이 만들되, 화면 어딘가에 «연습용» 표지는 유지한다(REPLAY 라벨과 같은 진실성 장치이자 사칭 방지).

### 수업 운영

9) **발맞춤은 앱이 강제하지 않는다** — 개인 페이스 + 미션 순차 개방(현 `earnedMissionIndex` 방식의 연장). 교사 발맞춤은 구두 + 시연 모드. «수업 흐름은 교사가 정한다» 철학 유지 — 앱이 교실을 멈출 수 있는 자리(교사 잠금)를 만들지 않는다.
10) **교사 공부 재료는 설명 노트 한 곳** — 체험이 있는 문항의 노트에 «체험 운영» 섹션을 추가(학생이 치게 될 명령과 뜨는 화면 / 자주 막히는 지점 / AI 목소리가 어디까지 답하는지). 별도 실습 가이드 신설 금지 — 교안 부활이다. 노트에 적는 것은 «수업을 이렇게 진행하라»가 아니라 **«학생 화면에서 무슨 일이 일어나는가»**.

### 공사 방식

11) **골격 먼저 (에픽 순서는 §2)** — 철거 대상(챗봇 패널·내 차례 탭)이 전역 컴포넌트라, 시범강 먼저 가면 «12강만 챗봇이 없는» 반쪽 라이브가 생긴다. 골격 재편 직후에도 전 강이 «읽기 → 체험(견학형) → 퀴즈»로 온전하다.
12) **목업 = 화면 3벌 + 23강 내용 명세** — HTML 목업은 부품별 1벌(터미널형/유사 페이지형/견학형). 강별로는 **체험 명세 카드** 23장: 이 강의 부품, 짝 링크, 미션·대본, 산출물 슬롯 내용, **읽기 본문 개편 방향**. 유사 페이지의 «본뜨는 서비스» 종류가 늘면 그 종류별 목업만 추가.
    - 본문 재작성은 필수 — 현 본문이 철거될 탭(「내 차례에 넣고 보내세요」 등)을 직접 안내하고 있어, 골격만 바꾸면 유령 탭을 가리킨다.
13) **탭 이름 = «체험»** — 보기·치기·누르기를 다 덮어 전 강에서 참말이 되는 유일한 이름. `shared/ui-glossary.md` 등재 + 문구 계약 대상.
