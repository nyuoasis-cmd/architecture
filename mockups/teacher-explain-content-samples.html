ch01_q01 · 1/71 · 쉬움
컴퓨터는 결국 무슨 일을 하나요?
입력과 저장, 처리와 출력을 한 흐름으로 묶어 컴퓨터의 기본 동작을 잡습니다.
⚡ 1줄 요약 (A1) 컴퓨터는 결국 입력→처리→출력→저장 4단계를 빠르게 반복하는 기계입니다.
🎯 수업 목표
학생이 일상에서 마주치는 컴퓨터 동작을 4단계 흐름(입력·처리·출력·저장)으로 환원해서 설명할 수 있다.
💬 교사 멘트 (시연 시작 멘트)
"여러분이 지금 보는 화면도, 결국 4단계 중 하나예요. 어디일까요?"
📖 개념 설명
컴퓨터는 키보드·마우스 같은 입력으로 명령을 받아, CPU가 처리하고, 화면·스피커로 출력하며, 메모리·디스크에 저장합니다. 이 네 단계가 1초에 수십억 번 일어나죠.
⚙️ 작동 방식 (비유 1 + 기술 1)
식당에 비유하면 주문(입력)→주방조리(처리)→음식제공(출력)→레시피기록(저장)입니다. 기술로 보면 키보드 신호가 CPU 명령어로 변환되고 결과가 화면 픽셀로 출력됩니다.
🌍 실생활 연결
카카오톡 메시지 보내기도 똑같습니다. 글자 입력→서버 전송 처리→상대 화면 출력→DB 저장. 게임도, 결제도 모두 이 4단계의 변형이에요.
❓ 학생 질문 대응 (3~5개)
왜 4단계로 나누나요? 한 단계로 합치면 안 돼요?
각 단계의 부품이 다르기 때문이에요. CPU는 처리만, RAM은 저장만 잘하죠. 분업해야 빨라집니다.
스마트폰도 컴퓨터인가요?
네, 모든 단계를 가지고 있죠. 손가락 터치(입력)→앱 실행(처리)→화면 표시(출력)→사진 저장(저장).
처리는 누가 하나요?
CPU(중앙처리장치)예요. 컴퓨터의 두뇌라고 부르죠.
✅ 시연 전 체크
학생이 자기 폰을 꺼낼 수 있는지 확인하세요. 4단계 직접 실습이 핵심이에요.
⚠️ 학생 흔한 오개념 + 정정법
"컴퓨터는 인터넷이 있어야 작동한다"는 오해가 많아요. 인터넷 없는 계산기·메모장도 4단계를 모두 수행하는 컴퓨터예요. 인터넷은 입력·출력 통로 하나일 뿐입니다.
📌 교사 메모
4단계 도식은 6장 컴퓨터 구조에서 다시 등장. 여기서 익숙해지면 6장 진입 부담이 줄어듭니다.

데이터 정규화는 왜 필요한가?
중복을 줄이고 수정 실수를 막기 위해 데이터를 나누는 이유를 설명합니다.
⚡ 1줄 요약 (A1) 같은 정보가 여러 곳에 적혀 있으면 수정 사고가 나기 때문에, 한 곳에만 적도록 나눕니다.
🎯 수업 목표
학생이 데이터 중복으로 생기는 수정 오류 사례를 1개 이상 들 수 있다.
💬 교사 멘트
"친구 전화번호가 노트 5권에 적혀 있다고 해요. 번호 바꾸면 어디까지 다시 써야 할까요?"
📖 개념 설명
정규화는 한 정보를 한 자리에만 저장하도록 테이블을 쪼개는 작업입니다. 중복을 줄여 수정 누락 사고를 막죠.
⚙️ 작동 방식
학생 정보+학교 정보를 한 표에 같이 적으면, 학교 이름 바꿀 때 학생 수만큼 수정해야 합니다. 학교 표를 따로 두면 한 번만 수정하면 되죠.
🌍 실생활 연결
카카오톡 친구 이름을 1번 바꾸면 모든 대화방에서 자동 반영되는 것도 정규화 효과예요. 친구 이름이 메시지마다 따로 저장돼 있다면 수억 곳을 일일이 고쳐야 합니다.
❓ 학생 질문 대응
그럼 무조건 잘게 쪼개면 좋은 거예요?
아니요. 너무 쪼개면 조회할 때 표 여러 개를 합쳐야 해서 느려져요. 쓰임새 보고 절충합니다.
정규화 안 한 DB도 있나요?
있어요. 빠른 조회가 더 중요한 분석용 DB는 일부러 중복을 허용하기도 합니다.
왜 '정규화'라고 부르나요?
정해진 규칙대로 정리한다는 뜻이에요. 1차·2차·3차로 단계가 있죠.
✅ 시연 전 체크
칠판에 학생-학교 합친 표 그려놓고 시작하세요. 시각적 대비가 핵심이에요.
⚠️ 학생 흔한 오개념 + 정정법
"정규화하면 DB가 빨라진다"는 오해가 흔합니다. 정규화는 '정확성'을 위한 작업이고, 조회 속도는 오히려 느려질 수 있어요. 속도는 인덱스가 담당합니다.
📌 교사 메모
정규화 단계(1NF·2NF·3NF) 자체보다 "왜 쪼개나요?"라는 동기 설명에 시간 쓰세요. 단계 암기는 부담만 됩니다.

ch04_q01 데이터란 무엇인가 ch07_q01 RDBMS와 NoSQL
ch07_q01 · 36/71 · 중상
RDBMS와 NoSQL은 무엇이 다른가?
고정된 구조와 관계를 중시하는 방식과 유연한 문서·키값 구조를 중시하는 방식을 비교합니다.
⚡ 1줄 요약 (A1) RDBMS는 표·관계 중심이고, NoSQL은 문서·키값처럼 유연한 구조를 받아들입니다.
🎯 수업 목표
학생이 RDBMS·NoSQL 각각에 적합한 사례를 1개씩 들 수 있다.
💬 교사 멘트
"엑셀 표가 어울리는 데이터는 어떤 거고, 자유 일기장이 어울리는 데이터는 뭘까요?"
📖 개념 설명
RDBMS(관계형 DB)는 정해진 열·행 구조에 데이터를 채우고 표끼리 관계를 맺습니다. NoSQL은 JSON 같은 유연한 묶음으로 저장해 구조 변경이 자유롭죠.
⚙️ 작동 방식
도서관에 비유하면 RDBMS는 분류 코드대로 책장에 꽂는 방식, NoSQL은 책마다 메모지를 붙여 쌓아두는 방식이에요. 기술로는 SQL 쿼리 vs JSON 조회 API 차이입니다.
🌍 실생활 연결
은행 계좌·학생 성적표는 RDBMS, 인스타 게시물·게임 캐릭터 데이터는 NoSQL이 흔해요. 정확성이 핵심이면 RDBMS, 자유로운 변형이 잦으면 NoSQL입니다.
❓ 학생 질문 대응
그럼 NoSQL이 더 좋은 거예요?
용도가 달라요. 정확한 정산이 필요한 곳엔 RDBMS가 안전하고, 자주 바뀌는 게시물엔 NoSQL이 편합니다.
둘 다 쓰는 회사도 있나요?
네, 대부분이 그렇습니다. 결제는 RDBMS, 추천 데이터는 NoSQL처럼 섞어 씁니다.
NoSQL은 왜 'No' 인가요?
Not Only SQL의 줄임말이에요. SQL을 안 쓴다기보다 '꼭 SQL일 필요 없다'는 뜻입니다.
✅ 시연 전 체크
학생들에게 익숙한 카카오·인스타·은행 앱 떠올리게 하고 시작하세요.
⚠️ 학생 흔한 오개념 + 정정법
"NoSQL이 RDBMS의 차세대 버전"이라는 오해가 있어요. 두 방식은 용도가 다른 도구이고, RDBMS는 50년째 현역입니다. 새 것이 더 좋은 게 아니에요.
📌 교사 메모
학생이 "그럼 우리 학교 시스템은 뭐예요?"라고 물으면 "성적은 RDBMS, 자유 글은 NoSQL일 가능성이 큽니다"로 답하세요.

ch10_q01 · 65/71 · 어려움
IaaS, PaaS, SaaS는 어떻게 다른가?
같은 클라우드라도 누가 어디까지 책임지는지에 따라 세 층으로 나뉜다는 점을 설명합니다.
⚡ 1줄 요약 (A1) 클라우드를 누가 어디까지 책임지냐로 IaaS·PaaS·SaaS 세 층으로 나눕니다.
🎯 수업 목표
학생이 IaaS·PaaS·SaaS 각각의 사용 예를 1개씩 들 수 있다.
💬 교사 멘트
"피자집에 비유해볼게요. 직접 굽기, 반죽 사오기, 완성품 사기. 클라우드도 비슷한 3층이에요."
📖 개념 설명
IaaS는 서버·디스크 같은 인프라만 빌리고 나머지는 직접 관리, PaaS는 OS·실행환경까지 제공받고 코드만 올리면 되며, SaaS는 완성된 앱을 그냥 쓰는 형태입니다.
⚙️ 작동 방식
피자에 비유하면 IaaS는 재료만 받기, PaaS는 반죽까지 받기, SaaS는 완성 피자 받기예요. 기술로는 AWS EC2(IaaS)·Render(PaaS)·구글 드라이브(SaaS)가 대표입니다.
🌍 실생활 연결
우리가 매일 쓰는 카카오톡·구글 드라이브·노션은 모두 SaaS예요. 회사가 카카오톡을 만든 게 아니라 카카오의 완성 앱을 그냥 쓰는 거죠.
❓ 학생 질문 대응
어느 게 가장 비싼가요?
고정값은 없어요. 다만 손이 덜 가는 SaaS가 단위당 가격은 비싸고, 직접 관리하는 IaaS는 운영 인력이 더 듭니다.
학교에선 어떤 걸 쓰나요?
대부분 SaaS예요. 구글 클래스룸·교육행정시스템 등 완성 앱을 그대로 씁니다.
왜 3개로 나누나요?
선택지를 주는 거예요. 제어를 원하면 IaaS, 빠르게 만들고 싶으면 PaaS, 그냥 쓰고 싶으면 SaaS로.
✅ 시연 전 체크
학생들이 매일 쓰는 SaaS(카톡·유튜브) 먼저 짚고 시작하세요. 친숙함부터 출발해야 IaaS까지 따라옵니다.
⚠️ 학생 흔한 오개념 + 정정법
"클라우드=인터넷 저장소"라는 오해가 큽니다. 저장은 클라우드의 한 기능일 뿐, 실제로는 서버·DB·AI까지 모두 빌려 쓰는 개념입니다.
📌 교사 메모
3층 비유는 시험에 자주 나옵니다. 피자 비유로 한 번 각인시키면 학생이 1년 뒤에도 기억해요.
